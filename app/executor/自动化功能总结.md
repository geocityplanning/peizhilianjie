# 139云应用平台自动化 — 功能总结

---

## 一、实现了哪些功能

共 6 个功能，每个都是独立调用，不需要同时执行：

| 序号 | 功能 | 一句话说明 |
|------|------|-----------|
| 1 | 自动登录 | 检测登录状态，过期自动填账号密码+识别验证码登录 |
| 2 | 创建渠道 | 在139后台新建一个渠道，重名自动加后缀，返回渠道完整记录 |
| 3 | 创建应用 | 复制模板应用，填写配置，保存，上线，设置分组，返回整行完整数据 |
| 4 | 修改应用 | 对已存在的应用做增量修改，只改传入的字段，返回修改前原值+修改后整行 |
| 5 | 定位应用 | 通过渠道名+应用名模糊匹配找到历史应用，返回整行完整数据 |
| 6 | 查询记录 | 超时或断线后，查之前的任务执行到哪了，不重新执行 |

**核心原则**：所有功能返回的都是后台最新全量数据。不管是创建、修改还是定位，调用方拿到的都是该应用/渠道在后台的完整信息，可直接存库，随时可用。

---

## 二、每个功能需要什么信息，返回什么

### 1. 自动登录

**需要什么**：无（账号密码已加密存在配置文件里）

**返回**：
```json
{"success": true, "message": "登录成功", "already_logged_in": false}
```
```json
{"success": false, "message": "登录失败：验证码重试5次仍未成功"}
```

**说明**：session 有效时直接返回"已登录"，过期时自动走完整登录流程。

### 2. 创建渠道

**需要什么**：
- 渠道基础名（如 `he0820`）
- 底座名称（可选，不传默认"华为底座2.0"）

**返回（成功）**：
```json
{
  "success": true,
  "message": "操作成功",
  "actual_channel_name": "he0820",
  "channel_data": {
    "id": "969",
    "firstLetter": "H",
    "channel": "he0820",
    "appNum": 0,
    "basePlatform": "2",
    "creator": "weiweitest",
    "deleteFlag": 0,
    "createTime": "2026-08-26 16:19:45",
    "updateTime": "2026-08-26 16:19:45"
  }
}
```

| 返回字段 | 说明 |
|---------|------|
| actual_channel_name | 实际渠道名（重名时自动加后缀，如 he08201） |
| channel_data.id | **渠道ID**，FastAPI 存库后可直接用 |
| channel_data.channel | 渠道名（和 actual_channel_name 一致） |
| channel_data.basePlatform | 底座ID（2 = 华为底座2.0） |
| channel_data.creator | 创建人 |
| channel_data.createTime | 创建时间 |
| channel_data.appNum | 该渠道下已绑定的应用数量 |
| channel_data.* | 其他后台字段全量返回 |

**返回（失败）**：
```json
{"success": false, "message": "创建渠道异常：...", "error_code": "CHANNEL_CREATE_FAILED"}
```

**关键点**：`channel_data` 是从后台 API 拉取的完整渠道记录，FastAPI 可整条存 SQLite，以后改应用时直接用 `channel_data.id` 精确匹配，不需要再模糊查找。

### 3. 创建应用

**需要什么**：

| 字段 | 必填 | 说明 |
|------|------|------|
| business_object | 是 | 业务对象（如"中国移动云盘"），用来找模板 |
| activity_name | 是 | 活动名（和 business_object 拼成应用名） |
| actual_channel_name | 是 | 所属渠道名（从创建渠道的返回值拿） |
| application_type | 是 | "云盘"或"掌厅" |
| jump_address | 是 | 调起路径 |
| resource_fallback_page | 是 | 资源不足中间页链接 |
| settlement_type | 是 | 结算类型（云盘/在线/市场化结算等） |
| group_name | 否 | 云机链接分组（如10028，空则跳过分组设置） |

**返回（成功）**：
```json
{
  "success": true,
  "message": "操作成功",
  "cloud_app_link": "https://plus.buy.139.com/mccloudgame/#/?i=RL775r9LuYM=",

  "row_data": {
    "序号": "1",
    "ID": "11945",
    "应用名称": "中国移动云盘-活动1",
    "所属渠道": "he0820",
    "应用链接": "https://l.yun.139.com/m/a/s/6APV3",
    "长连接": "https://plus.buy.139.com/mccloudgame/#/?i=RL775r9LuYM=",
    "版本号": "6.3.4",
    "体验时长": "每天不限时",
    "创建时间": "2026-08-26 08:58:43",
    "创建人": "weiweitest",
    "状态": "",
    "白名单": "设置",
    "云机链接": "设置",
    "底座": "华为底座2.0",
    "结算类型": "云盘",
    "操作": "复制预览编辑删除",
    "_status": "ON"
  }
}
```

| 返回字段 | 说明 |
|---------|------|
| cloud_app_link | **长链接**（正式环境开头不同），回填 Excel 用这个 |
| cloud_app_short_link | 短链接（l.yun.139.com/m/a/s/...），备查 |
| row_data | **整行全量数据**（17个字段），动态读表头，后台改列顺序不影响 |
| row_data.ID | **平台ID**（如11945），FastAPI 存库后下次直接用 |
| row_data._status | 状态开关值（ON/OFF），表格"状态"列文本读不到，单独提取 |

**返回（失败）**：
```json
{"success": false, "message": "保存失败(对话框未关闭) | 表单校验错误: xxx", "error_code": "SAVE_FAILED"}
```

### 4. 修改应用

**需要什么**：
- app_name（目标应用名）
- fields_to_update（要改的字段，JSON键值对）

**三种语义**：

| 字段在JSON中 | 含义 | 行为 |
|-------------|------|------|
| 有值 | 设新值 | 覆盖原值 |
| 空字符串"" | 清空 | 删掉后台原值 |
| 键不存在 | 不动 | 保留后台原值 |

**返回（成功）**：
```json
{
  "success": true,
  "message": "操作成功",
  "app_name": "中国移动云盘-活动1",
  "updated_fields": ["一句话简介", "应用图标"],
  "previous_values": {
    "一句话简介": "旧值",
    "应用图标": "old_icon.png"
  },
  "final_status": "ONLINE",
  "row_data": {
    "ID": "11945",
    "应用名称": "中国移动云盘-活动1",
    "所属渠道": "he0820",
    "应用链接": "https://l.yun.139.com/m/a/s/6APV3",
    "长连接": "https://plus.buy.139.com/mccloudgame/#/?i=RL775r9LuYM=",
    "底座": "华为底座2.0",
    "结算类型": "云盘",
    "_status": "ON",
    "...": "（整行17个字段全量返回）"
  }
}
```

| 返回字段 | 说明 |
|---------|------|
| updated_fields | 实际修改了哪些字段（按后台label） |
| previous_values | 修改前的原值快照，**可用于回撤**：把它当 fields_to_update 再调一次 |
| final_status | 修改后重新上线的状态（ONLINE/OFFLINE） |
| row_data | **修改后整行全量数据**，和创建应用返回的格式完全一致 |

**返回（失败）**：
```json
{"success": false, "message": "...", "error_code": "SAVE_FAILED"}
```

**需要什么**：
- execution_id 或 idempotency_key（至少一个）

**返回**：原任务的完整执行结果（和当初返回的一模一样，含所有 row_data / channel_data）

## 三、返回数据的统一设计

### 为什么所有功能都返回全量数据

| 场景 | 没有 row_data 的问题 | 有 row_data 的好处 |
|------|---------------------|---------------------|
| 创建应用后要改 | 得再调一次定位 | 直接用返回的 row_data.ID 精确匹配 |
| 修改后要回填 Excel | 只知道改了什么，不知道现在的完整状态 | row_data 是修改后的最新整行，直接回填 |
| 定位历史应用 | 只拿到一个 ID，其他信息没有 | 整行全量返回，存库即用 |
| 批量操作中断恢复 | 只有部分信息，不知道完整状态 | 查 get_execution 拿回完整 row_data |

### row_data 字段一览（动态读取，不硬编码）

| 列名 | 示例值 | 说明 |
|------|--------|------|
| 序号 | "1" | 当页序号 |
| ID | "11945" | **平台ID**，全局唯一 |
| 应用名称 | "中国移动云盘-活动1" | |
| 所属渠道 | "he0820" | |
| 应用链接 | "https://l.yun.139.com/m/a/s/6APV3" | 短链接 |
| 长连接 | "https://plus.buy.139.com/mccloudgame/..." | **长链接**，回填用 |
| 版本号 | "6.3.4" | |

## 四、自动化方式

### 默认方式：通过浏览器操作UI

所有功能默认通过 **CDP（Chrome DevTools Protocol）连接 Chrome 浏览器**（自动探测，找不到 Chrome 用 Edge 兜底），像人一样操作页面。

### 渠道列表查询：用API

渠道名查重直接调后端API拉全量列表（自算签名头），比翻页快。

### 兜底方式：MCP协议

如果不走直接 import，可通过 MCP 协议调用，6 个 Tool 输入输出格式完全一致。

---

## 五、健壮性设计

### 1. 幂等：同一个任务不会执行两次

同一个 idempotency_key 重复调用只返回原结果，不重新操作后台。

### 2. 单实例锁：同时只有一个在操作浏览器

第二个调用返回 EXECUTOR_BUSY。

### 3. 自动登录：session 过期不用管

每个功能执行前先调 ensure_login，过期自动登录，验证码失败重试最多5次。

### 4. 全链路错误捕获

每个步骤后检查弹窗是否关闭、开关是否变化、列表是否出现新记录、页面有没有红色错误提示。失败时截图保存。

### 5. 错误信息格式

```json
{
  "success": false,
  "message": "保存失败(对话框未关闭) | 表单校验错误: 应用名称不能为空",
  "error_code": "SAVE_FAILED",
  "error_stage": "SAVE",
  "next_action": "MANUAL_CHECK"
}
```

| 字段 | 说明 |
|------|------|
| message | 人话说明，可直接给业务人员看 |
| error_code | 机器错误码 |
| error_stage | 出错阶段 |
| next_action | STOP / QUERY / MANUAL_CHECK |

## 六、两种调用方式

### 方式一：直接 import（推荐，FastAPI 用）

```python
from actions.api import create_channel, create_app, update_app, locate_app, get_status, login

result = create_channel(channel_base_name="he0820")
# result["channel_data"]["id"] → 渠道ID

result = create_app(business_object="中国移动云盘", ...)
# result["cloud_app_link"] → 长链接
# result["row_data"]["ID"] → 平台ID

result = update_app(app_name="中国移动云盘-活动1", fields_to_update={...})
# result["previous_values"] → 修改前原值（用于回撤）
# result["row_data"] → 修改后整行

result = locate_app(channel_name="he0820", app_name="中国移动云盘-活动1")
# result["row_data"]["ID"] → 平台ID（下次直接用）
```

### 方式二：MCP 协议（Hermes 用）

6 个 Tool：get_executor_info / create_channel_tool / create_app_tool / update_app_tool / locate_app_tool / get_execution。输入输出都是 JSON 字符串，和直接 import 的返回值完全一致。

两种方式调的是同一套底层代码，行为一致。
